# 1. module定義
這個module主要用途是：決定「還進來的錢」要怎麼分配。沖銷用

# 2. 核心邏輯：
核心邏輯：
    還款順序 (Waterfall)：
        Tax (GST)：稅金最優先。
        Penalty：滯納金/罰息。
        Interest：利息。
        Principal：本金。
    部分還款 (Partial)：支援不完全還款，依上述順序填坑，剩餘部分掛帳。
    溢繳處理 (Excess)：多還的錢暫存入 Excess Bucket 或退款。
    強耦合：計算結果直接 Call Ledger 寫入。

---

# 3. 需求文件

## 3.1 這個模組在做什麼？(業務背景)

用戶還錢進來，這筆錢要怎麼分配？是先還利息還是先還本金？
這個模組就是負責做這個**分帳**的計算。

**白話說：** 這是貸款系統的「分錢機」。

### 為什麼需要這個模組？

1. **法規要求** — 還款順序有規定（稅 > 罰息 > 利息 > 本金）
2. **部分還款** — 用戶可能只還一部分，需要正確分配
3. **溢繳處理** — 用戶可能多還了錢，需要處理多餘的部分

### Waterfall 是什麼？
就像瀑布一樣，錢從上往下流，先填滿上層才會流到下層：

```
        ₹5,000 進來
            │
            ▼
    ┌───────────────┐
    │   GST (稅)    │ ← 先填這裡，假設欠 ₹200
    │   -₹200       │
    └───────────────┘
            │
            ▼ 剩 ₹4,800
    ┌───────────────┐
    │  Penalty (罰) │ ← 再填這裡，假設欠 ₹150
    │   -₹150       │
    └───────────────┘
            │
            ▼ 剩 ₹4,650
    ┌───────────────┐
    │ Interest (息) │ ← 再填這裡，假設欠 ₹1,000
    │   -₹1,000     │
    └───────────────┘
            │
            ▼ 剩 ₹3,650
    ┌───────────────┐
    │ Principal(本) │ ← 最後填這裡
    │   -₹3,650     │
    └───────────────┘
```

## 3.2 主要功能清單

| # | 功能名稱 | 說明 | 優先級 |
|---|---------|------|-------|
| 1 | **Waterfall 計算** | 按順序分配還款金額 | P0 |
| 2 | **部分還款處理** | 錢不夠時，按順序盡可能分配 | P0 |
| 3 | **溢繳處理** | 多還的錢存入 Excess Bucket | P0 |
| 4 | **提前還款計算** | 計算提前清償需要的金額 | P1 |
| 5 | **沖銷紀錄** | 記錄每次沖銷的明細 | P1 |
| 6 | **退款處理** | 溢繳金額的退款邏輯 | P2 |

## 3.3 業務場景說明

### 場景 1：正常還款（正好 EMI）
```
訂單狀態：
    - 應還 EMI：₹5,000
    - 其中本金：₹4,000，利息：₹1,000
    - 無罰息
    ↓
用戶還款 ₹5,000
    ↓
knockoff 計算：
    1. GST：₹0（無欠款）
    2. Penalty：₹0（無罰息）
    3. Interest：₹1,000 ✓
    4. Principal：₹4,000 ✓
    ↓
通知 ledger 入帳
```

### 場景 2：有逾期罰息
```
訂單狀態：
    - 應還 EMI：₹5,000（本金 ₹4,000，利息 ₹1,000）
    - 逾期罰息：₹200
    - 罰息的 GST：₹36
    ↓
用戶還款 ₹5,500
    ↓
knockoff 計算：
    1. GST：₹36 ✓
    2. Penalty：₹200 ✓
    3. Interest：₹1,000 ✓
    4. Principal：₹4,264 ✓
    ↓
剩餘本金減少 ₹4,264
```

### 場景 3：部分還款
```
訂單狀態：
    - 應還 EMI：₹5,000（本金 ₹4,000，利息 ₹1,000）
    - 逾期罰息：₹200 + GST ₹36
    ↓
用戶只還 ₹500
    ↓
knockoff 計算：
    1. GST：₹36 ✓
    2. Penalty：₹200 ✓
    3. Interest：₹264 (只夠還部分利息)
    4. Principal：₹0
    ↓
還欠 ₹736 利息 + ₹4,000 本金
```

### 場景 4：溢繳
```
訂單狀態：
    - 剩餘本金：₹10,000
    - 當期 EMI：₹5,000
    ↓
用戶還款 ₹6,000
    ↓
knockoff 計算：
    - 沖銷 EMI ₹5,000
    - 溢繳 ₹1,000
    ↓
溢繳金額存入 Excess Bucket
    ↓
之後可選擇：
    1. 抵扣下期 EMI
    2. 沖銷本金
    3. 退還用戶
```

## 3.4 Waterfall 優先順序

| 順序 | 項目 | 英文 | 說明 |
|-----|------|-----|------|
| 1 | 稅金 | GST | 政府的錢最優先 |
| 2 | 滯納金 | Penalty / Late Fee | 逾期產生的罰款 |
| 3 | 罰息 | Penal Interest | 逾期產生的額外利息 |
| 4 | 利息 | Interest | 正常利息 |
| 5 | 本金 | Principal | 最後才還本金 |

> ⚠️ 這個順序可能因產品而異，需要可配置

## 3.6 大概會怎麼開發

### Step 1：取得應還明細
- 從 ledger 或訂單取得目前欠款明細
- 包含：本金餘額、應計利息、罰息、稅金

### Step 2：Waterfall 計算
- 按順序逐一扣除
- 每一層記錄扣了多少

### Step 3：呼叫 Ledger
- 把計算結果轉成會計分錄
- 呼叫 ledger 寫入

### Step 4：溢繳處理
- 如果有剩餘金額
- 存入 ExcessBucket 表

## 3.7 和其他模組的關係

```
            ┌─────────────┐
            │     pay     │
            └──────┬──────┘
                   │ 收到還款 (MQ)
                   ▼
            ┌─────────────┐
            │  knockoff   │  ◄── 你在這裡
            └──────┬──────┘
                   │ 沖銷分配
                   ▼
            ┌─────────────┐
            │   ledger    │
            └─────────────┘
```

**通訊建議：**
- `pay → knockoff`：**MQ**（付款事件觸發）
- `knockoff → ledger`：**同步呼叫（需原子性）**

**不建議獨立**，原因：
1. 和 ledger 強耦合，需要原子性操作
2. 邏輯相對簡單，沒必要拆分

## 3.9 重要設計考量

| 項目 | 建議 |
|-----|------|
| **原子性** | 沖銷 + 入帳必須在同一事務 |
| **可配置** | Waterfall 順序可配置，不同產品可能不同 |
| **精度** | 金額計算用 BigDecimal，避免浮點誤差 |
| **日誌** | 每次沖銷詳細記錄分配明細 |
