# 1. module定義
這個module主要用途是：法律文件生成與銀行帳戶綁定。簽約用

# 2. 核心邏輯：
核心邏輯：
    KFS 生成：產出合規的關鍵事實聲明 (PDF)，揭露 APR 與手續費。
    Penny Drop：打入 1 Rupee 驗證用戶銀行帳戶有效性。
    e-Sign：觸發 Aadhaar 電子簽章流程。
    e-NACH：設定自動扣款授權 (Auto-debit Mandate)。
    狀態鎖定：簽約完成 -> 觸發放款指令 (Disbursal Ready)。

# 3. 需求文件

## 3.1 這個模組在做什麼？(業務背景)

貸款核准後，在真正放款之前，需要完成一系列**法律程序**：
1. 讓用戶知道他要付多少錢（KFS 文件）
2. 確認他的銀行帳戶是有效的（Penny Drop）
3. 讓他簽名同意（e-Sign）
4. 設定未來自動扣款（e-NACH）

**白話說：** 這是貸款系統的「法務部」+「銀行帳戶驗證員」。

### 為什麼需要這個模組？

1. **合規要求** — RBI 強制要求揭露 KFS（Key Fact Statement）
2. **防止詐欺** — 驗證銀行帳戶是本人的，避免錢匯到錯誤帳戶
3. **自動扣款** — 設定 e-NACH 後，還款日可以自動從用戶銀行扣錢
4. **法律效力** — 電子簽章在印度有法律效力

## 3.3 業務場景說明

### 場景 1：完整簽約流程 (Happy Path)
```
用戶收到核准通知
    ↓
1. 系統生成 KFS 文件
    - 顯示：貸款金額 ₹50,000
    - 年利率 18%、處理費 2%
    - 每月 EMI ₹4,576
    - 逾期罰息說明
    ↓
2. 用戶確認看過 KFS
    ↓
3. 用戶輸入銀行帳號
    ↓
4. 系統執行 Penny Drop
    - 打 ₹1 到用戶帳戶
    - 驗證：帳號姓名 = 申請人姓名 ✓
    ↓
5. 觸發 e-Sign
    - 發送 Aadhaar OTP 到用戶手機
    - 用戶輸入 OTP 完成簽章
    ↓
6. 設定 e-NACH
    - 用戶授權自動扣款
    - 設定每月 5 號扣款
    ↓
7. 簽約完成！通知 loancore 可以放款了
```

### 場景 2：Penny Drop 失敗
```
用戶輸入銀行帳號
    ↓
系統執行 Penny Drop
    ↓
失敗！原因可能是：
    - 帳號不存在
    - 帳號姓名和申請人不符
    - 帳號已凍結
    ↓
通知用戶重新輸入正確的銀行帳號
    ↓
用戶最多可以重試 3 次
```

### 場景 3：簽約超時
```
用戶收到核准通知，但一直沒來簽約
    ↓
過了 7 天...
    ↓
系統自動將訂單狀態設為 EXPIRED
    ↓
用戶如果還想借，需要重新申請
```

## 3.4 KFS 文件內容 (RBI 規定)

KFS (Key Fact Statement) 是 RBI 強制要求的揭露文件，必須包含：

| 項目 | 說明 | 範例 |
|-----|------|------|
| 貸款金額 | 核准的本金 | ₹50,000 |
| 年化利率 (APR) | 包含所有費用的實際年利率 | 21.5% |
| 名目利率 | 不含費用的利率 | 18% |
| 處理費 | 一次性收取 | ₹1,000 (2%) |
| EMI 金額 | 每月還款金額 | ₹4,576 |
| 期數 | 還款期數 | 12 期 |
| 總還款金額 | 本金 + 利息總計 | ₹54,912 |
| 逾期罰息 | 每天逾期的罰則 | 每日 0.1% |
| 冷靜期 | 用戶可無條件取消的天數 | 3 天 |
| 預付罰則 | 提前還款是否有罰則 | 無 |

## 3.6 大概會怎麼開發

### Step 1：KFS 生成
- 建立 KFS 模板（可用 iText, Apache PDFBox）
- 填入訂單資料產生 PDF
- 上傳到 S3 或檔案伺服器

### Step 2：Penny Drop
- 對接銀行 API 或第三方服務（Razorpay, Cashfree）
- 先扣 ₹1，確認成功後比對姓名
- 記錄驗證結果

### Step 3：e-Sign
- 對接 Aadhaar e-Sign 服務（NSDL, eMudhra）
- 發送 OTP → 驗證 OTP → 取得簽章憑證
- 將簽章嵌入 PDF

### Step 4：e-NACH
- 對接 NPCI 或 PG（Razorpay Mandate）
- 建立授權 → 用戶確認 → 啟用授權

## 3.8 和其他模組的關係

```
            ┌─────────────┐
            │   origin    │
            └──────┬──────┘
                   │ 核准 Offer
                   ▼
            ┌─────────────┐
            │    sign     │  ◄── 你在這裡
            └──────┬──────┘
                   │ 簽約完成
                   ▼
            ┌─────────────┐
            │     pay     │
            └─────────────┘
```

**通訊建議：**
- `loancore → sign`：**同步呼叫**（關鍵路徑）
- `sign → loancore`：**事件通知**（簽約完成、超時）
- `sign → pay`：不直接呼叫，透過 **loancore 協調**

## 3.10 印度特有注意事項

| 項目 | 說明 |
|-----|------|
| **Aadhaar e-Sign** | 印度國民 ID 的電子簽章，需要 OTP 驗證 |
| **e-NACH** | Electronic National Automated Clearing House，印度的自動扣款系統 |
| **Penny Drop** | 印度常見的銀行帳戶驗證方式，打 ₹1 並確認入帳 |
| **冷靜期** | RBI 規定用戶有權在 N 天內無條件取消貸款 |
| **CKYC** | 如果用戶有 CKYC，可以簡化 KYC 流程 |
