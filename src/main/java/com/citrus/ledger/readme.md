# 1. module定義
這個module主要用途是：會計module，目前先收到MQ即可。

# 2. 核心邏輯：
核心邏輯：
    複式簿記 (Double Entry)：借貸必相等 (Debit = Credit)。
    不可變性 (Immutable)：禁止 UPDATE 操作，餘額修正必須透過「紅沖藍補」。
    交易紀錄 (Journal)：記錄所有資金變動 (Disbursal, Repayment, Accrual, Write-off)。
    日結餘額：維護每日 Snapshot 以供快速查詢。

# 3. 需求文件

## 3.1 這個模組在做什麼？(業務背景)

這是貸款系統的**帳本**，所有錢的流動都記錄在這裡。
不管是放款、還款、計息、罰息、呆帳沖銷，通通都要記帳。

**白話說：** 這是貸款系統的「會計部門」。

### 為什麼需要這個模組？

1. **合規要求** — 金融業必須有完整的帳務紀錄
2. **審計需求** — 隨時可以查到任何一筆帳的來龍去脈
3. **餘額計算** — 知道用戶還欠多少錢
4. **財報基礎** — 公司財務報表的數據來源

### 複式簿記是什麼？

每筆交易都有「借方」和「貸方」，兩邊金額必須相等：

```
放款 ₹50,000 給用戶：

借 (Debit)：應收帳款 +₹50,000  (用戶欠我們的)
貸 (Credit)：銀行存款 -₹50,000  (我們的錢變少了)

兩邊都是 ₹50,000，平衡！
```

## 3.2 主要功能清單

| # | 功能名稱 | 說明 | 優先級 |
|---|---------|------|-------|
| 1 | **記帳 (Journal Entry)** | 接收事件，寫入會計分錄 | P0 |
| 2 | **餘額查詢** | 查詢某訂單目前的應收餘額 | P0 |
| 3 | **計息入帳** | 每日計息，生成利息應收 | P0 |
| 4 | **日結餘額** | 維護每日 Snapshot | P1 |
| 5 | **紅沖藍補** | 錯誤修正機制 | P1 |
| 6 | **帳務報表** | 生成帳齡分析、餘額報表 | P2 |

## 3.3 業務場景說明

### 場景 1：放款入帳
```
收到 pay 模組的 MQ：DISBURSEMENT_COMPLETED
    ↓
ledger 寫入分錄：
    借：應收貸款本金 +₹50,000
    貸：銀行存款    -₹50,000
    ↓
訂單帳務狀態：
    - 本金餘額：₹50,000
    - 利息餘額：₹0
```

### 場景 2：還款入帳
```
收到 knockoff 的呼叫：
    - 還本金：₹4,000
    - 還利息：₹1,000
    ↓
ledger 寫入分錄：
    借：銀行存款    +₹5,000
    貸：應收貸款本金 -₹4,000
    貸：應收利息    -₹1,000
    ↓
訂單帳務狀態：
    - 本金餘額：₹46,000
    - 利息餘額：₹0
```

### 場景 3：每日計息
```
loancron 觸發 ACCRUAL_RUN
    ↓
ledger 計算每筆貸款的當日利息：
    例：本金 ₹50,000，年利率 18%
    日息 = 50,000 × 18% ÷ 365 = ₹24.66
    ↓
寫入分錄：
    借：應收利息    +₹24.66
    貸：利息收入    +₹24.66
    ↓
訂單帳務狀態：
    - 利息餘額：+₹24.66
```

### 場景 4：紅沖藍補（錯誤修正）
```
發現昨天放款金額記錯了：
    實際放款 ₹48,000，但記成 ₹50,000
    ↓
不能直接 UPDATE，要這樣做：

1. 紅沖（沖銷錯誤的）
    借：銀行存款    +₹50,000
    貸：應收貸款本金 -₹50,000
    備註：紅沖 TXN-001

2. 藍補（重新記正確的）
    借：應收貸款本金 +₹48,000
    貸：銀行存款    -₹48,000
    備註：藍補 TXN-001
```

| 科目代碼 | 科目名稱 | 類型 | 說明 |
|---------|---------|------|------|

| 1210 | 應收利息 | 資產 | 已計提的利息 |

| 1230 | 應收費用 | 資產 | 處理費等 |
| 4100 | 利息收入 | 收入 | 利息收益 |
| 4200 | 罰息收入 | 收入 | 罰息收益 |
| 4300 | 手續費收入 | 收入 | 處理費收益 |
| 5100 | 呆帳損失 | 費用 | 壞帳沖銷 |

## 3.5 建議 API 清單

| API | 用途 | 呼叫者 | 備註 |
|-----|------|-------|------|
| `POST /ledger/entry` | 寫入分錄 | knockoff, 內部 | 核心 API |
| `GET /ledger/balance/{orderId}` | 查詢訂單餘額 | 各模組 | |
| `GET /ledger/journal/{orderId}` | 查詢分錄明細 | 後台 | 審計用 |
| `POST /ledger/accrual/run` | 執行計息 | loancron | 批次 |
| `GET /ledger/snapshot/{date}` | 查詢某日餘額快照 | 報表 | |
| `POST /ledger/reversal` | 紅沖藍補 | 後台 | 錯誤修正 |

**MQ 消費 (被動接收)：**
| 事件 | 來源 | 說明 |
|-----|------|------|
| DISBURSEMENT_COMPLETED | pay | 放款完成 |
| PAYMENT_RECEIVED | pay | 收到還款 |
| ACCRUAL_RUN | loancron | 計息觸發 |
| WRITE_OFF | loancore | 呆帳沖銷 |

## 3.6 大概會怎麼開發

### Step 1：定義科目表
- 建立 ChartOfAccount 表
- 配置科目代碼和類型

### Step 2：記帳 API
- JournalEntry 表：記錄每筆分錄
- 確保借貸平衡（Sum Debit = Sum Credit）

### Step 3：餘額計算
- 可以即時計算（SUM 所有分錄）
- 或維護 Balance 表（每次入帳更新）

### Step 4：計息 Job
- 每日凌晨執行
- 掃描所有 ACTIVE 訂單
- 逐筆計算日息並入帳

## 3.7 和其他模組的關係

```
     ┌─────────┐     ┌─────────┐     ┌──────────┐
     │   pay   │     │knockoff │     │ loancron │
     └────┬────┘     └────┬────┘     └────┬─────┘
          │               │               │
          │ MQ            │ 同步          │ MQ
          │               │               │
          └───────────────┴───────────────┘
                          │
                          ▼
                   ┌─────────────┐
                   │   ledger    │  ◄── 你在這裡
                   └─────────────┘
                          │
                          ▼
                   ┌─────────────┐
                   │   報表/審計  │
                   └─────────────┘
```

**通訊建議：**
- `pay → ledger`：**MQ（強順序，至少一次投遞）**
- `knockoff → ledger`：**同步呼叫（同一事務）**
- `loancron → ledger`：**MQ**

## 3.9 重要設計考量

| 項目 | 建議 |
|-----|------|
| **不可變性** | 分錄表只能 INSERT，永不 UPDATE/DELETE |
| **借貸平衡** | 每次入帳都驗證 Sum Debit = Sum Credit |
| **精度** | 用 BigDecimal 或 Long (分為單位)，避免浮點數 |
| **冪等性** | 用 唯一事件ID 避免重複入帳 |
| **審計軌跡** | 每筆分錄記錄操作人、時間、原因 |
| **日結快照** | 每日凌晨保存餘額 Snapshot，加速報表查詢 |
