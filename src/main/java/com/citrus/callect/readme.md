# 1. module定義
這個module主要用途是：催收

# 2. 核心邏輯：
核心邏輯：
    分桶策略 (Bucketing)：依 DPD 自動分類 (B0, B1, B2, NPA)。
    案件指派：
        輕微逾期 -> 自動發送 SMS/WhatsApp。
        嚴重逾期 -> 指派給催收代理 (Agency)。
    催記管理：記錄每一次催收互動結果 (PTP - Promise to Pay)。

---

# 3. 需求文件

## 3.1 這個模組在做什麼？(業務背景)

用戶逾期不還錢，這個模組就是負責**追債**的。
從發簡訊提醒，到打電話催收，到指派給外部催收公司，都在這裡管理。

**白話說：** 這是貸款系統的「催債部門」。

### 為什麼需要這個模組？

1. **降低壞帳** — 及時催收可以提高回收率
2. **分級處理** — 輕微逾期自動處理，嚴重的才人工介入
3. **合規要求** — 催收行為需要記錄，避免騷擾投訴
4. **外包管理** — 嚴重案件通常外包給專業催收公司

## 3.3 業務場景說明

### 場景 1：輕微逾期 (B0) - 自動催收
```
用戶逾期 1 天 (DPD = 1)
    ↓
loancron 通知 callect：新增逾期案件
    ↓
callect 檢查 DPD：1 天 → B0 分桶
    ↓
自動執行：
    1. 發送 SMS：「親愛的用戶，您的 EMI ₹5,000 已逾期...」
    2. 隔天再發一次
    3. 第 3 天發 WhatsApp
    ↓
用戶還款了 → 案件關閉
```

### 場景 2：中度逾期 (B1) - 電話催收
```
用戶逾期 35 天 (DPD = 35)
    ↓
callect 升級分桶：B0 → B1
    ↓
案件自動指派給內部催收員
    ↓
催收員打電話：
    - 結果：用戶說週五發薪水會還
    - 記錄：PTP (Promise to Pay) = 週五
    ↓
週五到了：
    - 用戶還款 → 案件關閉
    - 用戶沒還 → 標記 BPT (Broken Promise)，繼續催收
```

### 場景 3：嚴重逾期 (B2/NPA) - 外包催收
```
用戶逾期 65 天 (DPD = 65)
    ↓
callect 升級分桶：B1 → B2
    ↓
案件指派給外部催收代理 (Agency A)
    ↓
傳送案件資料給代理：
    - 用戶姓名、電話、地址
    - 欠款金額、逾期天數
    ↓
代理每週回報催收進度
    ↓
代理催回 → 結案並計算代理佣金
```

### 場景 4：PTP 追蹤
```
催收員記錄：用戶承諾 1/15 還款 ₹3,000
    ↓
系統設定 PTP 追蹤：
    - 用戶：王小明
    - 承諾日期：1/15
    - 承諾金額：₹3,000
    ↓
1/15 到了：
    - 系統自動檢查是否有還款
    - 有 → PTP 成功
    - 沒有 → PTP 失敗，繼續催收
```

## 3.4 分桶策略 (Bucketing)

| Bucket | DPD 範圍 | 處理方式 | 責任人 |
|--------|---------|---------|-------|
| **B0** | 1-30 | 自動 SMS/WhatsApp | 系統 |
| **B1** | 31-60 | 電話催收 | 內部催收員 |
| **B2** | 61-90 | 外包催收 | 外部代理 |
| **NPA** | 90+ | 法律行動準備 | 法務+代理 |

---

## 3.5 催記類型 (Disposition Codes)

| 代碼 | 說明 | 後續動作 |
|-----|------|---------|
| PTP | Promise to Pay | 設定追蹤日期 |
| BPT | Broken Promise | 升級處理 |
| RTP | Refused to Pay | 考慮法律行動 |
| CB | Call Back | 安排回撥時間 |
| NA | No Answer | 重試 |
| WN | Wrong Number | 更新聯絡資訊 |
| LC | Left Company | 查找新聯絡方式 |
| PAID | 已還款 | 結案 |
| SETTLED | 已和解 | 結案 |

## 3.7 大概會怎麼開發

### Step 1：案件管理
- CollectionCase 表：催收案件
- 關聯到 LoanOrder

### Step 2：分桶邏輯
- 每日批次檢查 DPD
- 自動升級分桶

### Step 3：自動催收
- 對接 SMS Gateway (Twilio, MSG91)
- 對接 WhatsApp Business API

### Step 4：催記系統
- CollectionNote 表：催收紀錄
- PTP 追蹤邏輯

### Step 5：代理管理
- Agency 表：催收代理
- 案件指派和回報流程

## 3.9 和其他模組的關係

```
            ┌─────────────┐
            │  loancron   │
            └──────┬──────┘
                   │ 逾期通知 (MQ)
                   ▼
            ┌─────────────┐           ┌─────────────┐
            │   callect   │──────────▶│   loancore  │
            └──────┬──────┘  狀態更新  └─────────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ 外部催收代理    │
          └─────────────────┘
```

**通訊建議：**
- `loancron → callect`：**MQ**（逾期通知）
- `callect → loancore`：**MQ**（催回成功通知）
- `callect → pay`：可選（強制扣款請求）

## 3.11 印度特有注意事項

| 項目 | 說明 |
|-----|------|
| **催收時間限制** | RBI 規定只能在 08:00-19:00 打電話 |
| **催收次數限制** | 每天不能打太多電話，避免騷擾 |
| **語言** | 印度多語言，SMS 模板要支援多語言 |
| **隱私保護** | 催收時不能向第三人透露欠款資訊 |
| **投訴處理** | 要有機制處理用戶對催收的投訴 |
